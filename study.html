PAT で設定する（所有者向け）

private リポジトリのデータを読むため、Fine-grained PAT をこの端末に保存します。 発行: GitHub → Settings → Developer settings → Fine-grained personal access tokens。 Repository access は mat-dev-io/LIFE のみ、Permissions は Contents: Read-only のみにしてください。 トークンは localStorage に保存され、GitHub API 以外へは送信されません。

共有用トークンの作成: 共有専用に発行した読み取り PAT をパスワードで暗号化します（空欄ならこの端末の PAT を使用）。 出力された JSON を assets/shared-token.json としてコミットすると、 パスワードを知っている人が閲覧できるようになります。

⌄

今週の、積み上げ。

週 4 時間のコアが、合否を決める最低ラインです。

4つの数字。時間と、実力。

時間は積み上げたか。正答率は上がったか。

週の学習時間

点線 = 週 4 時間のコア目標

合否に効くのは、山場の一日ではなく週の総量です。点線を割った週が続いていたら、計画ではなく生活動線のほうを直します。

日ごとの学習時間

記録が無い日は 0 時間として描く

毎朝 15 分の積み上げか、週末のまとめ取りか。棒の並び方が、いまの学習の形そのものです。空白が 3 日続いたら、まず 1 問だけ解いて線を切らないようにします。

演習の正答率

分野別演習（drill）の 正答 ÷ 問数。点線 = 合格ライン 60%

同じ日に複数分野を解いた日は合算しています。問数が少ない日は 1 問の重みが大きいので、点ではなく傾きで読みます。

累積と、必要ペース

実線 = 実績の累積、点線 = 週 4 時間で進んだ場合

点線より下にいる差が、取り戻すべき時間です。試験日は動かないので、この差は先送りするほど週あたりの必要量に跳ね返ります。

いつ、何を解いたか。

曜日の癖と、分野の偏り。

曜日のかたち

曜日別の平均学習時間（学習しなかった日も 0 として含む）

崩れるのは特定の曜日です。平日が全滅しているなら、平日の枠を増やすより、崩れない曜日に厚みを寄せるほうが続きます。

分野別の正答率

期間内の 正答 ÷ 問数（問数の多い順）。分野名は転記時に正規化済み

弱点は、正答率が低い分野ではなく「低いのに問数が少ない分野」に隠れています。棒が短くて問数も少ないものから手を付けます。
